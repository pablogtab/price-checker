# Domain Docs

## Layout

Single-context: API and frontend share the same domain vocabulary.

- `GLOSSARY.md` at the repository root.
- `docs/adr/` for architectural decisions.

## Consumer rules

Before exploring, read the glossary and ADRs relevant to the task.

If these documents do not exist, proceed silently. Do not create empty
placeholders or suggest creating them upfront. Domain-modeling skills
create them when terms or decisions are resolved.

Use glossary terms consistently in tickets, specifications and code proposals.
If a needed concept is missing, note it for domain modeling.

Surface conflicts with existing ADRs explicitly; do not silently override them.
